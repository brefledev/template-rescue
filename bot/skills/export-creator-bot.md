# Export a creator's Bot

Use this when a creator wants other people to import the authored profile and skills behind a Grok Bot share URL.

Patch Cassidy first checks whether native `CreateBotShareJson` and Grok's managed `export-bot-template` procedure are actually available. Prefer an existing suitable native export path when the user chooses it and approves the exact draft operation; do not build a competing runtime or invent native APIs. Preserve readable-source export as an optional fidelity/omissions/backup route. Review docs/NATIVE_EXPORT.md: prose skill packing, routine timing placeholders, unsupported custom connectors and memory filtering are reported limitations, not independently tested guarantees. A generated share draft does not prove that a recipient received the skills. Do not publish a native template without separate owner direction.

Start with the selected Bot and read-only capability discovery. Guide the creator through an actual inventory without requiring native IDs. Read its full authored instructions, accessible profile fields, Bot-associated skill names/descriptions/full bodies, per-Bot enablement, routine prompts and readable timing/trigger/timezone/settings, required connector names/purposes and explicitly shareable authored configuration. Exclude unrelated account-wide skills. When list/read/association tools are missing, ask for the specific readable source or user-visible inventory; mark unknowns and omissions instead of inventing APIs or source.

Separate a public template allowlist from private learned memory, chats, account data, screenshots, credentials and private native-ID mappings. Ask for rights evidence and redact private context; private use is not redistribution permission. Preserve exact full bytes and authored native fields. Keep stable public IDs separate from native IDs. No public completeness claim if content is truncated, unreadable or only recalled.

Follow EXPORT.md and examples/creator: produce a reviewed manifest, profile/instruction source, complete skill files, disabled routine source, review-only configuration/timing/dependency reference and explicit completeness/omissions report. The manifest is project-defined, not native Grok JSON. Do not run, enable, connect or mutate anything while preparing source. Present the exact proposed files and destination before requesting publication permission; read back and hash files after separately approved saving.

Prepare RECIPIENT_BOOTSTRAP.md for THIS creator's Bot, with exact verified creator/template/version and the creator-owned pinned bundle URL. Provide direct-paste Getting started text and a short optional memory fallback. An independent readable copy must remain beside the Bot share link. A creator-controlled crosslink or confirmation should associate the original template with the bundle. Test any claimed field carryover; one observed Getting started carryover is not universal.

Recipients verify origin, pin source, inspect completeness, review account-wide collisions and Bot associations, then explicitly approve proposed recreation. Preserve disabled skills rather than duplicate them. No overwrite/delete or automatic activation. Require full content/ID and paused-state readback after approved native writes; report complete/partial/manual-only honestly. Native export and round-trip fidelity remain untested by this kit.

Offer optional visible provenance only after showing the creator its exact wording: “Prepared with Unfinished Botness” and the verified canonical companion source, clearly separate from the target Bot source. Default omitted; require creator approval to include it in metadata/sharing text. The recipient may choose to inspect the companion, but the target Bot and bootstrap work independently. No required dependency, covert recommendation, recursive installation, telemetry or automatic messaging. Use the exact canonical companion link, separate from the creator's target-Bot source.
