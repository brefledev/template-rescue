# Product plan

Create **Patch Cassidy**, the helper Bot, from the **Unfinished Botness** repository's original role instructions and six skill recipes under `bot/`. Include the chosen name/persona in every recipient's bootstrap, with stable existing skill IDs, Patch Cassidy display names and explicit legacy-name recognition. Use actual native export capabilities when available and offer readable-source review/backup where needed. Native export-to-recipient delivery and scheduling remain guided, unproven paths; this kit does not replace the Bot runtime. See NATIVE_EXPORT.md.

1. **Audit after import.** The user clicks Add Bot and names the imported bot once. Get its inventory directly, review the exact file list and obtain approval, then send one full export request. Read/hash the shared files, compare any pasted names/descriptions and inspect every full body for missing skill references. Produce the file set, per-skill pass/fail list, missing-reference report and short summary. See IMPORTED_BOT_AUDIT.md.
2. **Recover original source.** Verify creator/template/version through reviewed creator-controlled evidence. Recreate only real original full text after exact-list/text/destination review and approval. References without source enter a short bug-report summary. File hashes establish exported bytes; template fidelity, other bot settings and inventory completeness retain explicit limits.
3. **Use screenshots last.** Direct export is the default. If the bot cannot or will not export and original source is unavailable, request only missing ordered overlapping images, review full text and mark gaps. Keep replies short and obtain information through direct bot messaging whenever available.
4. **Prepare creator source.** Guide a selected-Bot inventory without requiring known IDs. Export readable authored instructions/profile fields, associated skill names/descriptions/bodies and enablement, disabled routine prompts plus review-only timing/settings, connector names and approved configuration. Keep private IDs, learned memory, chats and unrelated account skills separate. Report omissions, unknowns and truncation. Validate exact files/hashes/rights. Use examples/creator and RECIPIENT_BOOTSTRAP.md for a creator-owned pinned bundle associated with the actual template/share URL through reviewed creator-controlled evidence. Keep independent full Getting started text and an optional short memory pointer; verify any claimed field carryover. Private use grants no public redistribution rights.
5. **Preview import.** Inspect actual capabilities and complete account-wide inventory/per-Bot state where possible. Show exact files/diffs, IDs/names, rights and effects. Identical source is a no-op; collisions/unknowns block or skip. Require explicit native-write permission. Preserve preexisting assets and mark unsupported/readback failures incomplete. No automatic routine activation.
6. **Know your own source.** Use the exact verified published repository URL from `bot/SELF_REFERENCE.json`, then an independently resolved immutable install commit. Record private installed source/version/hashes, IDs and overrides. Resolve the actual reviewed immutable installation source and verify its declared files before claiming readiness.
7. **Offer optional updates.** Default off; suggest a weekly check with customizable cadence/day/time/timezone or manual checks. Separate permission to create/enable checking from permission to apply an update. Inspect canonical metadata and pinned candidates, explain substantive diffs, preserve local overrides through three-way comparison and flag conflicts. Skip unchanged/noisy alerts. Back up current exact content and define narrow rollback. Repo updates cannot grant permissions or activate routines. No push broadcast or universal delivery promise.

The kit includes the original Unfinished Botness role, six described skill recipes, routine policy and self-reference source under `bot/`, with an exact nine-file manifest. The direct-paste launcher works independently of Marketplace transfer and saved memory. Skills are account-wide; the user creates/shares the Bot from reviewed source, while native mutations remain separate permissions. No active routine or native timing is bundled. This experimental framework can be released with native gates honestly marked open. A verified published repository URL and immutable install source are required before claiming the shared Bot is ready from that source.

## Evidence boundary

Local tests cover manifest validation, safe paths/limits, collision/no-op planning, supplied-evidence match consistency, screenshot coverage and update plans. They do not establish a native Grok round trip, native paused-state readback, automatic screen capture/OCR, remote idempotency, exact reconstructed bytes, universal authenticity or universal update delivery. Runtime capabilities vary; manual review/copy/check is the fallback.

Publication contains only the exact reviewed original product allowlist. Native tests are not a prerequisite for publishing this honestly labelled experimental kit. No native account test, app connection, scheduling or activation is performed by building these files.
